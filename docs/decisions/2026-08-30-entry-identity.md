# Entries are identified by slug; views keep sequence numbers; beads users mint a `decision` bead

## Context and Problem Statement

Every ADR convention in the ecosystem, MADR included, names files `NNNN-title.md` with a
zero-padded sequence. Under [the-decision-register](2026-08-29-the-decision-register.md)'s
binding-on-write ruling, that becomes unsafe: agents record concurrently from separate worktrees of
the same repo, two sessions both read the high-water number, both write `0060-*.md`, and git merges
them cleanly. Two decisions silently share an id — the same failure class as writing an unminted
bead id, which has shipped three times in this org. Sequential allocation needs a coordinator, and
tier 0 has no tooling at all.

## Considered Options

* Keep zero-padded sequence numbers, with lint catching duplicates after the fact
* Date-prefixed slugs
* Random/ULID ids
* Derive identity from the work tracker

## Decision Outcome

**Entries: `YYYY-MM-DD-<slug>.md`, and the slug is the identity.** Unique per register; the
citation handle is `<repo>#<slug>`. No allocator at any tier; self-describing in a grep hit, which
is the property the whole tier-0 story rests on; and a collision means someone re-decided a settled
question, which is a signal worth raising rather than an accident to prevent.

**Views: zero-padded sequence numbers, unchanged.** They are generated by one tool in one pass, so
allocation is serialized by construction, and the numbering preserves the familiar `ADR-000N`
surface people already read and cite.

**Where a work tracker exists, mint a `decision`-type bead** and record its id in `register.bead`.
The bead id is then the stable short reference. This is reuse rather than invention: `bd` is
already a collision-free distributed allocator with a store, a dependency graph and cross-store
links.

* The **file is the source of truth**; the bead is an index entry. On divergence, the file wins.
* **Mint before you cite** — bead first, then the file carrying its id, never the reverse.
* A `decision` bead makes the decision-landed → re-validate-open-work trigger a dependency edge
  rather than a new subsystem, and gives cross-register references the existing link-bead
  machinery.
* **Beads MUST NOT be assumed by the base pattern.** A register with no tracker is fully
  conformant. This is a tier-1+ affordance.

### Consequences

* Good, because concurrent autonomous recording is safe without a coordinator.
* Good, because `the_grid#no-file-watching` tells a reader what the precedent is; `the_grid#0047`
  does not.
* Bad, because slugs are verbose in prose where `A47` was four characters. Lint caps slug length.
* Bad, because a slug is as unrenameable as a number once cited. No worse, but no better.
* Neutral, because migrated legacy entries keep numeric `legacy-id`s, so registers end up mixed.
  That is accurate rather than untidy — the era genuinely changed.
